# blog29 공동 조사·토론

## 적용 범위

사람과 에이전트가 자료를 모으고 근거·해석·논리를 함께 정리하는 작업에 사용한다. 여러 가상 에이전트가 서로 동의하는 연극을 만들지 않는다. 기존 글 오탈자 수정에는 적용하지 않는다.

## 읽을 것

처음에는 저장소의 실제 적용 지침과 `docs/blog29/STUDIO.md`를 읽는다. 메모 생성 시에만 `docs/blog29/STUDIO-TEMPLATES.md`를 참고한다. 재개 시에는 지정된 주제의 `brief.md`, 최근 `discussion.md`, 현재 쟁점에 필요한 `sources.md` 부분만 읽는다. 작성 단계에서는 선택된 `story.vN.md`도 읽는다. 이 파일들이 없다고 읽은 척하지 않는다.

## 절차

1. **시작/재개:** 주제와 작업 경로를 식별한다. 여러 주제 중 대상이 불명확하면 하나만 확인한다. 파일 저장 전 Git/콘텐츠 로더/외부 전송 경계를 확인한다. 기존 작업과 사용자 원본을 보존한다.
2. **자료 접수:** 사용자가 준 파일·링크·메모를 읽는다. 원본은 바꾸지 않는다. `sources.md`에 유입 경로(user/agent), 출처 위치, 확인일, 자료 유형, 미확인 부분을 남긴다. 검색 결과나 요약만 읽었으면 원문 확인으로 표시하지 않는다.
3. **추가 조사:** 현재 논점의 빈틈·반대 근거·후속 검증을 먼저 찾는다. 외부 조사가 요청된 범위에서 실제 검색/추출 도구를 사용한다. 기본 한 라운드는 핵심 공백 최대 3개를 다루고 돌아온다. 이는 조정 가능한 작업 예산이지 정확도 기준이 아니다. 반복 검색으로 빈틈이 해소되지 않으면 유보한다.
4. **토론:** 새로 확인한 근거, 그 근거로 허용되는 해석, 대안 설명과 쟁점을 제시한다. 사용자 판단이 필요한 질문은 기본 1~2개만 묻고 답변을 기다린다. 반박할 이유가 없으면 억지 반박하지 않는다. 본문 전체를 아직 작성하지 않는다.
5. **기록:** 사용자의 실제 답변을 근거로 채택/수정/유보/기각을 `discussion.md`에 남긴다. 사용자 의견 채택으로 증거 상태를 승격하지 않는다. 새로운 주장이 생겼다면 그것을 뒷받침할 자료가 있는지 확인한다.
6. **기준본:** 구성 채택이 명시되면 `story.vN.md`에 질문·논지·주장 ID·제한·반론·목차·기준일을 고정한다. 기존 기준본은 덮어쓰지 않는다. 명시적 집필 요청이 함께 있으면 다시 승인 질문을 하지 않는다.
7. **산출:** 요청한 형식만 만든다. 블로그는 기존 `blog29-write`의 집필 절차를 사용하되 기준본을 바꾸지 않고 지정 작업 경로를 사용한다. 발표자료는 같은 기준본에서 별도의 슬라이드 구성안을 만든다. MDX를 슬라이드로 기계적으로 잘라 붙이지 않는다. 실제 렌더러가 없으면 발표 원고까지만 완료한다.
8. **검수/공개:** 내용 검수와 형식 검수를 구분한다. 산출물 위치와 주장 ID의 대응을 로컬 `review.md`에 기록한다. 공개 파일에는 정상적인 출처 표기를 쓰고 내부 ID/메모를 제거한다. 원격 변경은 별도 명시적 권한이 있을 때 기존 발행 규칙으로 수행한다.

## 정지 조건

- 질문을 제시하고 사람의 판단을 기다려야 할 때: `DISCUSS`.
- 증거가 더 없거나 접근 불가: `HOLD` 또는 한계를 명시한 `DISCUSS`; 관련 없는 설명까지 모두 중지할 필요는 없다.
- 자료/수치/논지가 바뀜: 영향을 받는 산출물을 `NEEDS_REVIEW`로 표시하고 재작성·재게시를 자동 실행하지 않는다.
- 작은 질문에는 답만 하고, 이미 합의된 구조를 불필요하게 다시 열지 않는다.

## 보고

현재 쟁점에 직접 답하고 필요한 근거와 질문을 제시한다. 끝에 상태와 실제 변경 파일을 짧게 알린다. 장황한 상태 보고로 토론을 대신하지 않는다. 실행하지 않은 검색·검증·렌더링·배포는 미실행/미확인으로 구분한다.
