# Studio 메모 템플릿

필요한 단계에서만 실제 작업공간에 복사한다. 예시의 빈칸을 임의 사실로 채우지 않는다. 별도 데이터베이스나 파서가 필요한 형식은 아니다. 기존 brief/sources의 내용은 지우지 말고 보강한다.

## brief.md

```text
mode: studio
stage: INTAKE
workdir: [실제 승인 경로]
주제/slug:
핵심 질문:
사용자의 잠정 생각: [아직 없을 수 있음]
독자/발표 시간: [미정 가능]
자료 범위: 사용자 제공 + 공개 웹 조사 / 제공 자료만
외부 전송 금지 항목:
계획한 산출물: 미정 / 블로그 / 발표 / 둘 다
선택 기준본: 없음
현재 쟁점:
새 자료/재검토할 주장:
다음 한 단계:
현재 대화에서 허용된 범위:
형식 변환 도구/상태: 미확인
사이트 반영/commit/push: 기본 미허용
사용자가 실제 허용한 요청과 적용 범위:
```

권한 항목은 참고 기록이며 재개 시 현재 요청과 대조한다. 메모가 권한을 새로 만들지 않는다.

## sources.md — 자료와 주장

```text
# 자료

## S001 — [자료명]
유입: user / agent
원발행자/저자:
성격: 논문 / 공급업체 백서 / 문서 / 사용자 경험 / 아이디어 / 기타
원본 위치: 실제 URL 또는 파일 경로
발행일/버전: 미확인 가능
확인일:
읽은 범위: 페이지/절/표/그림; 원문/발췌/검색요약 중 무엇인지
보관한 발췌/추출 경로: 없으면 없음
제약: 접근 실패/그림 미검증/조건 누락 등
공개/재사용 범위: 미확인 가능

# 주장

## C001 — [정확한 주장 문장]
유형: 외부 주장 / 관찰·실측 / 시뮬레이션 / 사용자 경험 / 해석 / 가설
지지 근거: S001 p.X §Y [관련 부분의 짧은 요약]
반대/제한 근거:
조건/단위/버전/대상:
검증 상태: 원문 내 주장 확인 / 조건부 지지 / 상충 / 미확인 등
편집 상태: 제안 / 채택 / 유보 / 기각
원고에서 허용할 표현:
판단 철회 조건: 분석적 판단이 아니면 해당 없음
기준일/재검토 계기:
```

## discussion.md

```text
## D001 — [날짜/쟁점]
검토한 질문:
관련 주장: C001
에이전트가 확인한 자료/이견:
사용자의 실제 응답 요지:
편집 결정: 채택 / 수정 / 유보 / 기각
결정 이유:
증거 상태 변화: 없음 / 새 근거를 실제 확인한 경우만 변경
다음 조사:
영향을 받는 기준본/산출물:
```

## story.vN.md

```text
# 편집 기준본 vN

내용 기준일:
채택 상태: 제안 / 사용자가 채택
채택 근거: 사용자의 실제 요청 요지; 없으면 미승인
이전 버전/변경 이유:

## 질문과 목적
## 채택한 논지
## 설명 순서
각 절의 역할과 관련 주장 ID
## 필요한 근거와 자료의 성격
실측/시뮬레이션/가설 구분
## 반론과 한계
## 유보·제외할 주장
## 판단 철회 조건과 재검토 계기
단순 설명에는 해당 없음 가능
## 마지막에 제시할 결론의 범위
## 산출물별 구성 조건
블로그 독자·문체 / 발표 청중·시간·사용 형식
```

## review.md

```text
# 산출물 검수/대응표

기준본:
자료 확인 기준일:
대상 파일/실제 수정일 또는 확인 가능한 hash:

| 주장 | 블로그 위치 | 발표 위치 | 상태/남은 검증 |
| C001 | 실제 절 제목 | 실제 슬라이드 번호/제목 | 검토 필요 |

## 내용 검수
주장-출처 일치 / 강도 / 반론 / 유보 / 공개 가능한 정보
## 형식 검수
블로그: 실제 MDX 검사 대상과 결과
발표: renderer/버전/명령/결과와 실제 페이지 시각 검수 여부
## 게시 권한과 실행 결과
사이트 반영 / commit / push / 실제 배포 확인을 별도 기록
## 변경 전파
새 근거 → 바뀐 주장 → 재검토할 위치 → 완료/미완료
```
