## 이 글이 설명하는 것

최근 뉴스와 개발 블로그에서 **AI 에이전트(AI Agent)**라는 말을 자주 보지만, 정작 "에이전트가 정확히 무엇인가"를 처음부터 설명하는 글은 드물다. 대부분 이미 아는 사람끼리 전제만 공유한 채 이야기를 진행한다.

이 글에서는 두 가지를 순서대로, 처음 보는 독자 기준으로 설명한다.

1. AI 에이전트는 챗봇과 무엇이 다른가
2. 같은 LLM을 쓰는데도 결과가 달라지는 '하네스(harness)'란 무엇인가

핵심 결론은 한 문장이다. **에이전트를 만드는 것은 모델이 아니라, 모델을 감싸서 돌리는 구조(하네스)다.**

## 1단계: LLM이란 무엇이고, 무엇이 못 하는가

### LLM이란

LLM(Large Language Model, 대규모 언어 모델)은 "다음 텍스트를 예측하는 프로그램"이다. ChatGPT나 Claude 같은 서비스의 뒷단에 있는 것이 바로 이 LLM이다.

LLM이 할 수 있는 일은 본질적으로 하나다. **텍스트를 받아서, 텍스트를 돌려준다.**

```text
입력:  "1+1은?"
출력:  "2입니다."
```

여기까지가 우리가 흔히 쓰는 챗봇의 전부다. 질문을 하면 답이 한 번 나오고, 대화는 거기서 끝이다.

### LLM의 한계

LLM은 텍스트만 주고받기 때문에 세 가지 일을 **직접** 할 수 없다.

1. **코드를 실행하지 못한다.** "이 코드가 틀렸다"고 말할 수는 있지만, 실제로 돌려보지는 못한다.
2. **파일을 열지 못한다.** 내 컴퓨터의 파일 내용을 스스로 확인하지 못한다.
3. **결과를 검증하지 못한다.** 자신이 쓴 답이 맞는지 확인할 수단이 없다.

즉 LLM은 "말은 잘하지만, 손이 없는" 존재다.

## 2단계: 에이전트는 여기서 한 걸음 더 간다

### 에이전트란

**AI 에이전트(AI Agent)는 LLM에게 도구를 붙이고, 목표를 달성할 때까지 반복하게 만든 시스템이다.**

같은 질문을 예로 들어보자. "이 코드에서 버그를 찾아줘"라고 했을 때:

```text
[챗봇]
  → "버그는 42행에 있는 것 같습니다. 이렇게 고치세요."
  → (답만 텍스트로 출력. 확인은 사용자가 해야 함)

[에이전트]
  1단계: 코드를 읽는다        ← 파일 읽기 도구 사용
  2단계: 테스트를 실행한다    ← 터미널 도구 사용
  3단계: 에러 메시지를 확인
  4단계: 코드를 고친다         ← 파일 쓰기 도구 사용
  5단계: 다시 테스트 → 통과하면 종료, 실패하면 3단계로 복귀
```

여기서 "읽고, 실행하고, 보고, 고치고, 다시 실행하는" 반복 루프가 에이전트의 본체다. LLM은 매 단계에서 **"다음에 뭘 해야 하지?"를 결정만** 하고, 실제 행위는 모델 바깥의 프로그램이 수행한다.

> 쉽게 말하면: 챗봇은 '답을 말하는 사람'이고, 에이전트는 '도구를 써서 일을 끝까지 하는 사람'이다.

### 루프 안에서는 실제로 무슨 일이 일어나는가

가장 중요한 부분인데, 설명이 생략되는 곳이기도 하다. 한 단계를 자세히 보면 이렇게 된다.

```text
① LLM에게 현재 상황을 보낸다
   (원래 목표 + 지금까지의 대화 기록 + 도구 목록)

② LLM은 텍스트로 "다음 행동"을 답한다
   예: {"도구": "테스트 실행", "인자": {}}
   → 즉, LLM이 직접 테스트를 실행하는 것이 아니라,
     "테스트를 실행해 달라"는 요청이라는 텍스트를 만든다

③ 모델 바깥의 프로그램(하네스)이 그 요청을 읽어서
   실제로 터미널 명령을 실행한다

④ 실행 결과("에러: 42행, 인덱스 범위 초과")를 다시 LLM에게 보낸다

⑤ LLM은 결과를 보고 다음 행동을 결정 → ①으로 복귀
```

핵심은 ②번이다. **LLM은 아무것도 직접 하지 않는다.** "이 도구를 이렇게 호출해 달라"는 텍스트만 만들고, 진짜 실행은 하네스가 한다. 그리고 ④에서 결과가 다시 LLM에게 돌아와야 다음 판단이 가능해진다. 이 왕복(①→⑤)이 반복되는 것이 에이전트 루프다.

### 왜 이 차이가 중요한가

챗봇은 사용자가 매번 확인하고 지시해야 한다. 반면 에이전트는 "테스트가 통과할 때까지 고쳐"라고 목표만 주면, 중간 과정을 스스로 돌린다. 코딩, 데이터 분석, 문서 정리처럼 **여러 단계를 거쳐야 하는 작업**에서 이 차이가 크다.

## 3단계: 하네스(Harness)란 무엇인가

### 단어의 뜻부터

'Harness'는 영어로 원래 **말에게 채를 지어 쟁기나 마차를 연결하는 장비**를 뜻한다. 말은 힘(동력)을 가지고 있지만, 그 힘을 실제 일(쟁기질)에 연결하려면 채가 필요하다.

AI에서 '하네스'는 같은 비유다. **LLM이라는 '힘'을 실제 작업에 연결해 주는, 모델 바깥의 모든 구조**를 가리킨다. 2단계에서 본 "③번과 ④번을 담당하는 프로그램"이 바로 하네스다. LLM이 아닌 코드로 작성된 부분 전체 — 지시문, 도구 목록, 실행 코드, 결과 전달 로직까지 전부 포함한다.

### 하네스는 다섯 가지로 나뉜다

| 구성 요소 | 비유 | 구체적으로 무엇인가 |
| --- | --- | --- |
| 지시문(시스템 프롬프트) | 신입사원의 업무 매뉴얼 | "너는 이런 역할을 하고, 이런 규칙을 지키고, 이런 형식으로 답해"라는 기본 설정. 매 대화 시작 시 LLM에게 함께 전달된다 |
| 도구 정의 | 사용할 수 있는 장비 목록 | 파일 읽기·쓰기, 터미널 실행 등. 각 도구가 무엇을 하는지, 어떤 인자를 받는지 설명한 '스키마'(도구 사용법 명세서)를 LLM에게 보여준다 |
| 컨텍스트 관리 | 기억력 보조 | 대화 이력이 길어지면 요약하거나, 중요한 내용은 메모장에 적게 하는 장치. LLM은 한 번에 볼 수 있는 정보량이 제한되어 있어서 필수다 |
| 실행 환경 | 작업 공간과 권한 | 어떤 파일·명령·네트워크에 접근할 수 있는지 정한 격리된 공간(샌드박스). 위험한 명령이 실제 시스템으로 새어나가지 못하게 막는다 |
| 검증과 피드백 | 품질 검사 | 테스트 통과 여부, 문법 오류 검사 결과 등을 다시 LLM에게 보여줘 실수를 되돌리게 만드는 루프 |

### 왜 같은 모델인데 결과가 달라지는가

여기서 핵심이다. **모델(예: GPT-4o, Claude)은 '뇌'만 공급한다.** 그 뇌가 어떤 매뉴얼을 읽고, 어떤 도구를 들고, 어떤 작업장에서 일하며, 실수를 몇 번이나 되돌릴 수 있는지는 전부 하네스가 정한다.

같은 LLM API를 쓰는 두 에이전트 제품이 다른 결과를 내는 이유는 보통 다음 중 하나다.

1. **지시문이 다르다** — 역할 정의와 금지 사항이 다르면 행동도 달라진다.
2. **도구 설계가 다르다** — 도구를 3개로 묶느냐, 30개로 나누느냐에 따라 LLM의 선택 공간이 달라진다. 도구 설명(스키마)이 모호하면 LLM은 잘못된 인자로 호출한다.
3. **검증 루프가 있느냐 없느냐** — 테스트를 돌려서 오류를 회수하는 하네스는 첫 실수를 최종 결과로 남기지 않는다.

즉 "A 제품이 B 제품보다 잘한다"는 평가에서, 그 차이의 상당 부분은 모델이 아니라 하네스에서 온다.

## 에이전트를 볼 때 체크리스트

에이전트 제품을 쓰거나 만들 때, 다음 질문을 하면 하네스의 수준을 가늠할 수 있다.

1. **도구가 뭐가 있고, 설명이 얼마나 정확한가?**
2. **긴 작업을 어떻게 기억하는가?** — 요약·메모 같은 장치가 없으면 긴 작업에서 초기 지시를 잊는다.
3. **실수를 되돌리는 루프가 있는가?** — 검증 없이 한 번의 출력을 최종 결과로 내면, 오류율이 그대로 품질이 된다.
4. **권한 범위가 어디까지인가?** — 파일·네트워크 접근이 넓을수록 강력하지만, 위험도 커진다.

## 확인된 사실과 판단

**확인된 사실:** Anthropic의 공식 엔지니어링 문서와 OpenAI의 에이전트 문서는 모두 "에이전트는 도구를 가진 LLM 루프"로 정의하며, 워크플로우(순서가 정해진 자동화)와 에이전트(모델이 스스로 경로를 결정)를 구분한다.

**판단:** 실무에서 에이전트를 비교할 때는 모델 이름만 보고 판단하면 안 된다. 위 체크리스트 4가지가 하네스의 품질을 보여주기 때문이다. 이 판단은 "동일 모델을 다른 하네스에 넣으면 결과가 달라진다"는 관측이 반복적으로 확인되는 한 유효하다.

## 반증 조건과 유효기간

- 모델 자체의 장기 기억·자기 검증 능력이 하네스 설계보다 성공률에 더 큰 영향을 준다는 재현 가능한 비교 결과가 나오면, "하네스가 중요하다"는 판단을 수정해야 한다.
- 2026-08-16 기준으로 확인한 공식 문서와 제품 구조를 근거로 썼다. 에이전트 제품의 지시문·도구 스키마가 공개되지 않아 하네스 분석이 불가능한 상태가 고착되면, 이 글의 비교 방법은 적용 범위가 줄어든다.
