# 개선 효과를 확인하는 작은 비교 실험

이 패키지의 가설은 '짧은 상시 지침, 단계별 작업, 근거 기록, 발행 분리가 장문 프롬프트 하나에 모든 일을 맡기는 방식보다 관리 가능성을 높인다'이다. 사용자 모델에서 성능 향상이 측정된 사실은 아니다.

## 비교 조건
먼저 도구 호출이 정상 작동하는 동일한 Tabby/Hermes 환경을 고정한다. 서버·Hermes 버전, 모델 리비전, 양자화, 실제 chat template, 최대 문맥, 샘플링을 기록한다. 비교 도중 하네스나 모델을 바꾸지 않는다. 외부 검색 결과의 변동을 줄이려면 같은 공개 자료 묶음을 쓴다.

동일한 세 과제를 기존 AGENTS와 개선 AGENTS에서 각각 수행한다. 이것은 통계적으로 충분한 성능평가가 아니라 초기 회귀 검사다. 결과 변동이 크면 반복 수를 늘리되 단일 성공을 '안정적'이라고 보고하지 않는다.

1. 기존 글 일부를 제한된 범위에서 재작성: 사실·수치·범위를 바꾸지 않는가?
2. 같은 자료 묶음으로 새 글 초안: 핵심 주장과 인용이 대응하는가? 가짜 경험/출처를 넣지 않는가?
3. 가설이 포함된 의견 글: 사실과 해석, 판단 철회 조건, 적용 범위를 구별하는가?

## 실제로 기록할 항목
| 항목 | 측정 방법 |
|---|---|
| 근거 없는 핵심 주장 | 사람이 검사한 핵심 주장 중 실제로 지지되지 않은 문장 수 |
| 인용 오류 | 출처가 없거나 해당 문장을 지지하지 않는 인용 수 |
| 범위 밖 수정 | 요청하지 않은 파일/주장/수치 변경 수 |
| 도구 실패 | 실제 호출 시도 중 잘못된 도구명·인자·파싱 실패 수 |
| 사용자 재작업 | 실제 고친 문장 수, 측정했다면 편집 시간 |
| 글의 읽기 품질 | 저자가 두 원고를 비교해 판단하고 이유를 기록 |
| 발행 규칙 위반 | 승인 없는 커밋·푸시·배포 발생 여부 |

각 수치에는 분모나 검사 범위를 함께 기록한다. 시간이나 속도를 측정하지 않았다면 알 수 없음으로 둔다. 검사 도구 통과를 사실 정확도라고 기록하지 않는다.

## 유지·철회 기준과 유효 범위
같은 조건에서 핵심 주장 오류/무관한 변경이 줄고 사용자 재작업이 감소하면 해당 범위에서 유지할 근거가 생긴다. 반대로 규칙 부담만 늘고 결과가 개선되지 않으면 세부 문서를 줄여 핵심 AGENTS만 사용하거나 원래 방식으로 되돌린다. 승인 없는 발행이 발생하면 자율 발행을 중단하고 실제 권한 격리를 먼저 보완한다.

판단의 유효 범위는 테스트한 모델·양자화·템플릿·Hermes/Tabby 버전과 블로그 스키마다. 이 조건이 바뀌거나 같은 실패가 다시 나타나면 재검증한다. 예측 성공률과 처리 속도는 이 패키지에 포함하지 않는다.
