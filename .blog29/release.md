# blog29 사이트 반영·발행

이 파일의 절차는 운영 규칙이다. AGENTS.md는 권한 격리나 강제 보안 장치가 아니다. 실제 제한은 최소권한 자격증명, 실행 승인, 브랜치 보호, 배포 설정에서 적용해야 한다. 이 패키지는 그 설정을 변경하지 않는다.

## PREPARE: 로컬 사이트 반영
사용자가 사이트 파일 반영을 요청했을 때만 실행한다.

현재 Git 변경 상태를 읽고 기존 사용자 변경을 보존한다. 검토된 초안을 확인된 콘텐츠 경로로 복사하면서 실제 front matter와 타입을 따른다. 소유자가 지정한 제목/slug를 유지한다. 날짜는 사용자 지정이나 실제 작업 시각을 쓰고 기존 발행일을 편집일로 덮어쓰지 않는다.

MDX는 일반 Markdown과 같다고 가정하지 않는다. 코드 예시의 꺾쇠괄호·중괄호·미닫힌 코드 펜스·JSX·컴포넌트 등록을 실제 로더/빌드로 확인한다. 임의 import나 새 컴포넌트, 원격 스크립트 실행을 추가하지 않는다. 로컬 이미지의 실제 존재, 크레딧, 대체 텍스트와 링크 목적지를 확인한다.

`check_draft.py --publication`을 선택적으로 실행한다. 이것은 눈에 띄는 유출/placeholder/코드 펜스 오류 등의 보조 검사일 뿐, MDX/YAML 파서·사실 검증기·보안 스캐너가 아니다. 현재 프로젝트에 있는 lint/typecheck/build 명령을 확인하고 필요한 것을 실행한다. 없는 `lint` 스크립트를 만들어 통과시키지 않는다. 실패 로그가 의존성이나 환경 문제를 가리키면 글 내용 문제와 구분한다.

## 원격 Preview
사용자가 원격 검토를 요청하고 대상 저장소/브랜치가 확인된 경우에만 진행한다.

기존 브랜치와 스테이징 상태를 확인한다. 새 작업 브랜치를 만들 때도 기존 작업을 이동·삭제하지 않는다. 정확한 글/자산 파일만 스테이징한다. 전체 디렉터리를 무차별 추가하지 않는다. diff와 커밋 대상, 비밀/내부 자료/작업 메모 포함 여부를 검토한다. 관련 없는 staged 변경이 있으면 그것까지 커밋하지 않는다.

승인된 범위 안에서 커밋하고 원격 브랜치로 푸시한다. PR 생성이 요청되었으면 생성한다. Git 연동과 프로젝트 설정에 따라 Vercel Preview가 생성될 수 있다. 생성된 실제 URL과 상태를 확인하고 원고 페이지를 열어 렌더링·링크·코드 블록·이미지를 검토한다. 브랜치 이름에서 URL을 추측하지 않는다.

Preview URL은 비공개라고 가정하지 않는다. 미공개 투자 판단·사내 자료·개인정보는 Preview에도 보내지 않는다. 보호 상태를 확인하지 못했다면 외부에 공개되는 것으로 간주한다.

## Production
운영 발행은 별도 명시 승인이 필요하다. 운영 브랜치는 Vercel 프로젝트 설정 또는 사용자가 확인한 정보로 식별한다. Git 기본 브랜치가 운영 브랜치와 같다고 가정하지 않는다.

승인한 diff/커밋이 이후 바뀌면 변경된 범위의 승인을 다시 확인한다. 승인된 경로로만 병합/푸시/배포한다. 검사 실패를 숨기거나 우회하지 않는다. 운영 URL과 배포 상태를 확인하지 못했다면 '푸시 완료, 배포 확인 못함'처럼 구분해서 보고한다.

## 실패 및 무행동
아무것도 발행하지 않는 선택은 정상이다. 최신성·출처·렌더링·승인 중 중요한 것이 불확실하면 로컬 초안을 남기고 중단한다. 롤백도 원격 변경이므로 과거 커밋을 임의로 되돌리거나 이력을 강제로 수정하지 않는다. 필요하면 승인받을 되돌림안을 제시한다.
