# blog29 편집 기준

이 문서는 글을 구성하거나 편집할 때만 읽는다. 상시 프로젝트 규칙은 루트 AGENTS.md에 있다.

## 먼저 정할 것
작업 공간의 brief.md에 독자, 독자의 질문, 저자가 말하려는 한 문장, 자료 범위, 기존 글과의 차이, 분량/문체 요청을 짧게 기록한다. 사용자가 이미 준 내용을 다시 묻지 않는다. 애매함이 핵심 주장이나 발행 권한에 영향을 주지 않으면 가정을 명시하고 초안을 만든다.

이번 글과 가까운 기존 글 1개, 대표 글 1개를 읽어 시점(1인칭/설명형), 종결어미, 문단 길이, 소제목 방식, 용어 표기를 파악한다. 기존 글은 문체의 근거이지 최신 사실의 자동 증거가 아니다. 서로 다른 글의 말투를 무작정 혼합하지 않는다.

## 글의 종류에 맞게 구성
고정된 모든 소제목을 매번 강제하지 않는다.

- 개념 설명: 문제 → 필요한 개념 → 작동 원리 → 작은 예 → 한계 → 마무리.
- 구현 기록: 실제 목표/환경 → 실제로 한 일 → 코드/결과 → 오류와 한계 → 재현 조건. 실행하지 않은 코드는 예시라고 표시한다.
- 조사/의견: 질문 → 확인된 사실 → 해석 → 대안 설명/반례 → 판단이 바뀌는 조건 → 마지막 판단.
- 경험/에세이: 사용자가 제공한 관찰 → 의미 → 한계. 연구 보고서의 형식이나 가짜 통계를 붙이지 않는다.

서론에서 독자에게 문제의 맥락을 주되 끝의 결론을 그대로 반복하지 않는다. 중요한 전제나 안전상의 한계는 필요한 위치에서 즉시 밝힌다.

## 근거의 최소 단위
sources.json은 자료를 많이 모으는 목록이 아니라, 어떤 문장이 어떤 자료의 어느 부분에 기대는지 찾기 위한 기록이다. 기사/모델 소개가 '성능이 향상되었다'고 주장하면 '제공자는 향상을 보고했다'와 '독립적으로 검증되었다'를 구별한다. 벤치마크는 모델·양자화·하네스·평가 조건이 다른 수치를 단순 동급으로 비교하지 않는다.

기술 자료는 원문/공식 문서/실제 구현을 우선한다. 분쟁이나 해석이 있는 문제는 유의미한 반대 근거도 읽는다. 직접 읽지 못한 자료를 재인용할 때는 직접 열람한 2차 출처와 그 한계를 밝힌다. 최신 정보가 필요한데 검색/읽기 도구가 없다면 최신성을 보증하지 않는다.

긴 원문을 보관하거나 공개하지 말고, 필요한 위치와 짧은 발췌/자기 말로 한 요약을 남긴다. 내부 자료는 외부 검색어나 공개 파일로 보내지 않는다.

## 말투의 예시
나쁜 문장: '이 혁신적인 기술은 모든 기업의 업무를 완전히 바꿀 것입니다.'
좋은 문장: '이 방식은 작업 이력을 남기는 데 도움이 될 수 있습니다. 다만 기록이 누락되면 같은 판단을 재현하기 어렵습니다.'

나쁜 문장: '직접 실험해 보니 처리 속도가 두 배 빨라졌습니다.' — 실험 자료가 없을 때.
좋은 문장: '처리 속도에 대한 실측 자료는 없습니다. 아래 코드는 비교 실험을 위한 예시입니다.'

이는 교정 원리의 예시다. 위 문장을 실제 글에 상투적으로 복사하지 않는다.

## 출처의 내용을 본문에 녹이는 편집 원칙
**본문 완결성:** 독자는 원문 링크를 열지 않아도 해당 기술의 개념, 작동 원리, 구체적인 근거, 의미와 한계를 파악할 수 있어야 한다. 출처는 본문 설명을 대신하는 곳이 아니라 사실관계를 검증하고 더 깊게 읽는 경로다.

- "A 보고서에서 설명한다", "B가 강조한다", "공식 문서를 참고하라"로 논점을 마무리하지 않는다. 원문이 실제로 **무엇을 주장했고, 어떤 구조·방법·관찰·사례로 뒷받침했는지**를 먼저 자기 문장으로 서술한다. 그 다음 출처를 문장 가까이에 둔다.
- 논문·제품 구조·업계 조사에서 핵심으로 인용하는 자료는 최소한 **문제가 무엇이었는지 → 어떻게 접근했는지 → 무엇이 확인됐는지 → 무엇이 아직 확인되지 않았는지**를 필요한 깊이만큼 서술한다. 중요한 메커니즘은 입력·처리·출력 또는 기존 방식·변경 방식의 비교로 설명하고, 독자의 이해에 필요한 예시를 넣는다.
- 조사 결과나 성능 수치는 **발행 시점, 조사·측정 시점, 표본·분모, 측정 대상, 비교 기준, 한계**를 붙인다. 벤더의 실측 주장은 벤더가 보고한 결과로 귀속시키고 모든 환경에 일반화하지 않는다. 확인 불가능한 수치는 '알 수 없음'으로 명시한다.
- 자료의 사실과 저자의 해석을 문맥에서 구분하고, 반대 설명·적용 범위·철회 조건을 필요한 위치에 함께 배치한다. 원문에 없는 인과관계나 경험, 구현 완료 상태를 만들어내지 않는다.
- 저작권을 존중한다. 원문을 장문으로 복사하거나 표·그림 전체를 무단 재현하지 말고, 필요한 정보만 정확하게 재서술한다. 직접 인용은 짧게 사용하고 출처를 명확히 남긴다.
- 최종 점검에서 **출처 링크를 클릭하지 않아도 글의 주장과 작동 원리가 이해되는지** 확인한다. 핵심 내용이 링크에만 있다면 본문을 보완한다. 원문 확인이 불가능한 핵심 주장은 확정적으로 쓰지 않거나 발행을 보류한다.

## 최종 편집
내용 검토와 문장 편집을 분리한다. 먼저 핵심 주장, 인용, 숫자, 적용 조건을 검사한다. 다음에 어색한 문장, 반복, 소제목, 문단 연결을 다듬는다. 표현을 다듬다가 '가능성'을 '사실'로 바꾸지 않는다. 모든 문장을 동일한 길이나 리스트로 정규화하지 않는다.
